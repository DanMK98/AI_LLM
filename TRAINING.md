# Transformer training

Run these commands from the project root. Some historical examples below require
checkpoints that are not present in `experiments/`. The current `data/input.txt`
also differs from the corpus used to create some saved tokenizer and character
checkpoints, so those training and resume examples need matching artifacts.

To change the training batch size while resuming:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/finance_bpe_2048/latest.pt --batch-size 92 --steps 1000 --output-dir experiments/finance_bpe_2048
```

An explicit `--batch-size` overrides the saved training batch size. Omit it to
keep the saved value. New runs still default to 128. Evaluation batch size is
saved separately and remains unchanged on resume, preserving evaluation samples.
Older checkpoints use their original saved batch size for evaluation. Both batch
sizes are printed at startup. Optimizer state and learning rate are preserved.

## Subword BPE training

To train a new tokenizer (in case you apply a new training source), call for the following function:

.\.venv\Scripts\python.exe train_tokenizer.py --vocab-size 4096 --output-dir experiments/finance_bpe_4096

This will create a tokenizer.json and tokenizer_metadata.json files with the tokens extracted from the initial training text file.

Train a fresh model with the already prepared 2,048-token tokenizer:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --scratch --tokenizer experiments/finance_bpe_2048/tokenizer.json --batch-size 32 --steps 1000 --eval-every 200 --output-dir experiments/finance_bpe_2048
```

The first 80% and final 20% of raw text are encoded separately. If tokenizer
metadata is present, its corpus, split, and file fingerprint are checked. Both
checkpoints embed the full tokenizer JSON and fingerprint. Keep the JSON and
metadata as the reproducible tokenizer artifact; generation and resume use the
embedded copy. `--tokenizer` requires `--scratch`; it cannot replace a loaded
checkpoint's vocabulary. Existing character checkpoints retain their character
encoding (their weights must still match the current model's QKV layout).

The BPE experiment uses context 128 tokens, embedding 192, 4 heads, and 3 blocks
with the current defaults. Batch size 32 limits the memory cost of the larger
output vocabulary. This command uses fresh weights and a fresh optimizer. The
output directory may contain tokenizer files, but must not contain best/latest
checkpoints from an earlier run. After training:

```powershell
.\.venv\Scripts\python.exe generate_transformer.py --checkpoint experiments/finance_bpe_2048/best.pt --prompt "The interest rate" --length 128 --temperature 0.8
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/finance_bpe_2048/latest.pt --steps 1000 --output-dir experiments/finance_bpe_2048
```

For BPE, `--length` counts new subword tokens. Generated byte tokens may sometimes
decode to replacement characters if the sampled bytes do not form valid UTF-8;
this differs from encoding/decoding valid input, which should round-trip exactly.
The reported cross-entropy is per token and is not directly comparable with
character-model loss. New checkpoints record the text fingerprint and refuse
resume if data/input.txt changed; use a new weights-only run for a deliberate data
change. Old checkpoints without fingerprints remain loadable.

Run short temporary-checkpoint tests with:

```powershell
.\.venv\Scripts\python.exe -B -m unittest tests.test_subword -v
```

## Context-128 experiment

`prepare_context.py` supports larger contexts with
`--context-size`. To reproduce the context-128 initialization in an empty directory:

```powershell
.\.venv\Scripts\python.exe prepare_context.py --source experiments/transformer_context64_refine/best.pt --context-size 128 --output-dir experiments/transformer_context128
```

This copies all 64 trained position rows, initializes 64 additional rows with
normal(mean=0, std=1), and copies every other weight unchanged. It keeps 2 blocks,
embedding size 192, and 4 heads. The source checkpoint stays intact. A fresh Adam
optimizer, step zero, and fresh random states are saved in `initial.pt`.
Training settings are inherited from the source, including its learning rate.

Once prepared, train when ready:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/transformer_context128/initial.pt --learning-rate 0.0003 --steps 1000 --output-dir experiments/transformer_context128
```

The explicit learning rate uses the same initial adaptation rate as the context-64
experiment rather than the source's smaller refinement rate. New `best.pt` and
`latest.pt` files stay in `experiments/transformer_context128`. Continue later from its
`latest.pt`. The new position rows need training; extending context does not
guarantee coherent dialogue. In this implementation, doubling context makes each
attention score matrix four times larger, so training may use more GPU memory.

## Context-64 experiment

By default, `prepare_context.py` creates `experiments/transformer_context64/initial.pt` from
`experiments/transformer_finetune/best.pt` without training. It preserves the source file,
copies position embedding rows 0–31 exactly, and initializes rows 32–63 with
PyTorch's embedding default normal distribution (mean 0, standard deviation 1),
using seed 42. Every other model weight and architecture setting stays unchanged:
2 blocks, embedding size 192, and 4 heads. The output directory must be separate
and empty. The source path, SHA-256, step, and initialization seed are recorded.

The new checkpoint starts at step zero with a fresh Adam optimizer and new RNG
states. Training settings, including learning rate, are copied from the source.
Context-32 validation losses are not carried over as a context-64 best score.
Start the prepared experiment when ready:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/transformer_context64/initial.pt --steps 1000 --output-dir experiments/transformer_context64
```

Here `--resume` loads the prepared context-64 model with its empty optimizer state;
it does not restore the context-32 optimizer. Training first evaluates a context-64
baseline, then writes `best.pt` and `latest.pt` in `experiments/transformer_context64`.
For later continuation, resume that directory's `latest.pt`. To sample it, use
`generate_transformer.py --checkpoint experiments/transformer_context64/best.pt`.

To prepare another experiment, run `prepare_context.py --output-dir NEW_DIRECTORY`.

## Context-32 training

The trainer uses CUDA when available and otherwise CPU. `--device cpu` forces
CPU; `--device cuda` requires CUDA. The model and batches use the selected device.
The existing `checkpoints/best_transformer_2blocks.pt` is loaded by default and never overwritten.
Its architecture is 2 blocks, embedding size 192, context length 32, and 4 heads.
`TransformerLanguageModel` now accepts `num_layers` without changing weight names.

From PowerShell in the project directory, start training when ready:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --steps 10000
```

This loads existing weights with a fresh Adam optimizer and starts the new run's
step count at zero. The old file lacks optimizer and RNG state, so its training
trajectory cannot be resumed exactly. Use `--weights PATH` for another saved
transformer checkpoint, or `--scratch` to initialize fresh weights.
Checkpoint architecture and character ordering are used when loading weights.

New files are saved in `experiments/transformer_checkpoints/`:

- `latest.pt`: the most recent evaluation checkpoint, also saved at the final step.
- `best.pt`: the lowest validation loss, including an evaluation of the initial
  model before updates. It can therefore contain step zero and an empty Adam
  state if no updates improve on the loaded model.

Both contain model weights, optimizer state, completed training step, architecture
settings, best/current validation losses, vocabulary, seed tokens, training
settings, Python RNG state, PyTorch CPU/CUDA RNG states, and the independent
training-batch generator state. Evaluation uses a separate fixed seed (123).
Files are written through a temporary file and replaced once complete.
The default evaluation/save interval is 2,000 steps. Interruptions can lose work
since the last save. A new run refuses to overwrite existing output checkpoints.

Resume all training state, for example:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/transformer_checkpoints/latest.pt --steps 10000
```

`--steps` always means additional steps. Resume restores the saved batch size,
learning rate, evaluation interval, and evaluation batch count. An explicit
`--learning-rate` overrides the restored optimizer's learning rate; other training
settings retain their saved values. New weights-only or scratch runs default to
`0.0003`. Keep `data/input.txt` unchanged for reproducible continuation.
CPU/GPU transfers are supported, but bit-for-bit reproducibility across devices,
CUDA device counts, or PyTorch versions is not guaranteed. When resuming into a
new output directory, the resumed model establishes that directory's baseline
best; historical best weights are not copied from a different directory.

To continue from your best saved checkpoint with a tenfold lower learning rate,
preserving its optimizer history and writing into a separate directory:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --resume experiments/transformer_checkpoints/best.pt --learning-rate 0.0003 --steps 1000 --output-dir experiments/transformer_finetune
```

This preserves the original best/latest files. A lower learning rate makes updates
smaller but does not itself prevent overfitting; compare validation loss against
the saved baseline. No training is launched by changing this configuration.

For a one-step smoke check:

```powershell
.\.venv\Scripts\python.exe train_transformer.py --steps 1 --batch-size 2 --eval-batches 1 --output-dir experiments/smoke_checkpoints
```

The script does not train when imported, and no longer samples text automatically
after training. `legacy_archive/generate.py` targets the separate older
`legacy_archive/best_model.pt` model. To sample the current default BPE checkpoint
without training:

```powershell
.\.venv\Scripts\python.exe generate_transformer.py --length 500 --temperature 0.8
```

Use `--prompt "ROMEO:"` to supply starting text, `--seed 123` for another sample,
or `--checkpoint PATH` for a different transformer checkpoint. The script defaults
to `experiments/finance_bpe_2048/best.pt`, uses CUDA when available (CPU otherwise), and
never writes to the checkpoint. Lower positive temperatures concentrate sampling
on more likely tokens; higher temperatures increase variety.

Run the short integration tests with:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_training -v
```
